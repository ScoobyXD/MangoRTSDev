# CtrlLoop setup

This change prepares code and configuration only. It does not deploy services, apply database changes, create secrets, change Nylas settings, or enable production. Gmail direct links remain unresolved, so the requested Google workflow is incomplete. Microsoft link construction has synthetic tests but still needs signed-in provider qualification.

## Existing services and configuration

CtrlLoop reuses the managed OpenAI Agents client, Nylas grants and ingestion queue, the existing email worker, PostgreSQL, and S3 attachments. There is no separate Excel service to deploy: the backend exposes `/v1/ctrl-loop/mcp`, authenticated by an expiring token for one run. OpenAI connects to that HTTPS endpoint using its service transport. The token is generated by the worker and is not an operator secret.

| Setting | Value and purpose |
| --- | --- |
| `openai_api_key_secret_arn` | Exact existing Secrets Manager ARN containing a raw OpenAI API key. Default empty. ECS injects `OPENAI_API_KEY`; it does not put the key in Terraform values. |
| `ctrl_loop_enabled` | Default `false`. Supported only in dev and QA. Requires the configured SQS email worker, migrated queue schema, Nylas webhook integration, Valkey, database and S3. |
| `ctrl_loop_model` | Default `gpt-5.6-luna`; supported choices are Luna, Terra, Sol, and GPT-6 Astra using their API IDs. |
| `MANGORTS_CTRL_LOOP_MCP_URL` | Derived in ECS as `https://<existing-api-domain>/v1/ctrl-loop/mcp` only when enabled. API and worker receive the same value. |
| `MANGORTS_CTRL_LOOP_MODEL` | Derived from `ctrl_loop_model` for both processes. |

Supplying the OpenAI ARN without enabling CtrlLoop makes the existing interactive Mango AI available on the API. Only an enabled CtrlLoop worker receives that key. The API and worker execution-role policies grant `GetSecretValue` for that exact ARN; application task roles gain no general secret access. The supplied secret should use the existing Secrets Manager encryption/access convention; a customer-managed KMS key may require a separately reviewed decrypt grant.

For GitHub deployment configuration, dev accepts `TF_OPENAI_API_KEY_SECRET_ARN`, `TF_CTRL_LOOP_ENABLED` and `TF_CTRL_LOOP_MODEL`. QA accepts only the separate `TF_QA_OPENAI_API_KEY_SECRET_ARN`, `TF_QA_CTRL_LOOP_ENABLED` and `TF_QA_CTRL_LOOP_MODEL` variables. Enablement defaults to `false` and model to `gpt-5.6-luna`. Existing deploy workflows pass these settings to the existing modules. No production workflow or production stack is changed. Examples deliberately contain no real OpenAI ARN or key.

For a local API plus email worker, use the existing secure OpenAI configuration path (`OPENAI_API_KEY_SECRET_ARN`, or an already configured process-only `OPENAI_API_KEY`) and existing Nylas/S3/database/queue settings. Set both `MANGORTS_CTRL_LOOP_MCP_URL` and `MANGORTS_CTRL_LOOP_MODEL` consistently. The MCP URL must reach that local backend through an intentionally configured public HTTPS endpoint; `localhost` alone is unreachable from OpenAI. Do not write production credentials to a local file.

## Human-controlled rollout

1. Run the read-only `scripts/ctrl_loop_preflight.sql` in DBeaver and stop on any STOP result. Review and apply `20260913_ctrl_loop.sql`, then `20260913_z_ctrl_loop_attachments.sql`, through the existing migration process while the affected writers are stopped. Both target PostgreSQL 17 and 18; the second depends on the job table from the first. Do not apply them from application startup. Backend builds now require Go 1.25 for the maintained official MCP SDK; both backend Docker builders and the Go module are updated.
2. Confirm the existing email-worker, Nylas webhook, queue, Valkey, attachment storage and daily attachment recovery are configured in dev or QA. Use an isolated test mailbox and a harmless workbook.
3. Configure an existing OpenAI secret ARN with managed Agents API access and access to the selected model. Leave `ctrl_loop_enabled=false` until the review is complete.
4. In the authorized environment, enable the feature and deploy the same backend revision to API and email worker. Confirm the public MCP route rejects missing, expired and unrelated tokens and that OpenAI can connect with the exact current run token.
5. Complete the provider and workbook checks below before claiming the feature is ready. Keep production disabled; production release needs separate approval and completed qualification.

The repo does not assert that these rollout steps have occurred. Any existing deployments also need normal execution-role and task-definition updates for new secret injection; editing a GitHub variable alone does not update a running container.

## Required qualification still pending

Use a harmless mailbox fixture to confirm an Outlook hyperlink opens its exact source message from a fresh browser, after the message moves folders, and with multiple provider accounts signed in. Confirm the arrival text is the Nylas mail-server receipt time in the selected timezone, including daylight-saving transitions. The tests use Microsoft native-shaped fixture IDs; they cannot establish actual browser behavior.

Gmail currently fails explicitly before workbook updates. Nylas exposes native Gmail IDs but not a verified browser permalink. A complete Google solution must first establish a usable exact-message or exact-thread link for the connected account, then qualify fresh-browser and multiple-account clicks. Do not substitute a search URL or an internal Mango viewer. [Provider evidence](ctrl-loop-provider-contracts.md) explains the verified fields and unresolved link contract.

With OpenAI, verify a real managed session imports only the explicit Excel tool allowlist, stages the intended cells, terminates successfully, and saves the version atomically. Re-deliver the same email and restart the worker during processing to check duplicate handling. Confirm the downloaded workbook preserves sheets, formulas and unrelated cells while each successful changed cell contains literal arrival text and a clickable provider link. These live OpenAI/provider checks have not been performed with customer data or credentials.

Setting `ctrl_loop_enabled=false` removes MCP/model configuration and prevents new workbook activation. Existing activated jobs still accept their eligible incoming mail durably; processing reports a configuration error until restored. SQS owns retries and dead-letter delivery; redrive a dead-lettered run only after fixing its cause. Preserve job records and workbook versions; removing settings does not authorize deleting their files. Removing a job through its owner lifecycle marks unowned versions for the existing cleanup process.
