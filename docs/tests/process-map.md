# Process Map Business Logic Laws

1. Process Map MUST reference the exact canonical Company Explorer Folder and Process identities and MUST NOT create copied Folder or Process entities.
2. Process is the product name for the existing Logic Gate resource and MUST reuse the exact existing Logic Gate identity and records.
3. The company canvas MUST contain only Company Explorer Folders and Processes; a focused Process authoring canvas MUST use that Process's Step layout rather than company placements.
4. Folder names and facts MUST come from `company_explorer_folders`, and Process names and facts MUST come from the canonical Logic Gate records.
5. Current source names and permissions MUST be joined when Process Map is read and MUST NOT be copied into Process Map storage.
6. Company Explorer MUST be the sole authority for Process Map inclusion and structural parentage; `process_map_placements` MUST own only the exact typed source reference, its Explorer-mirrored parent, snapped global geometry, positive dimensions, revision, and timestamps.
7. `resource_operational_relationships` MUST be the authority for operational flow between supported resources.
8. `process_map_traces` MUST be the authority only for the saved visual routing of an operational relationship.
9. Manually saved Process Map geometry and trace routing MUST remain canonical map facts, while placement existence and parentage MUST remain a synchronized projection of Company Explorer rather than an independent authority.
10. Process Map MUST NOT introduce a resource registry, surrogate resource identity, translated identity, copied resource payload, or compatibility identity layer.
11. Process Map MUST have one shared continuous canvas per company and MUST NOT add separate map records.
12. Process Map generic resource references MUST use the exact canonical stored types `company_explorer_folder` and `logic_gate`; the Process display name MUST NOT create a parallel stored `process` identity.
13. Every Company Explorer Folder and every `company_explorer_items` row whose exact target type is `logic_gate` MUST have exactly one Process Map placement in its company.
14. Projects, Nodes, and every other unsupported Company Explorer target MUST have no Process Map placement.
15. Every Process Map placement parent MUST equal its exact Company Explorer parent; a null Explorer parent MUST produce a root placement.
16. A root placement MUST have no map parent and MAY reference either a root Folder or a root Process.
17. A non-root placement MUST name the exact same-company Company Explorer Folder that directly parents that Folder or Process.
18. A Process MUST NOT parent another Process Map placement.
19. Canonical Company Explorer commands MUST reject Folder self-parenting, descendant cycles, missing parents, and cross-company parents before the Process Map projection changes.
20. A Folder's exact canonical ID MUST identify its Company Explorer Folder and matching Process Map fence and MUST NOT identify a separate Process Map layer or route.
21. Deleting a Folder from Process Map MUST use the canonical Company Explorer target-deletion command and inherit its protection, authorization, recycle, and subtree-cleanup behavior.
22. A live Company Explorer Folder MUST always have one Process Map fence and MUST have no separately openable Process Map layer or URL.
23. Creating, moving, or deleting a supported resource in Company Explorer MUST synchronize its Process Map placement in the same committed operation; same-parent reordering MUST preserve existing Process Map geometry.
24. Renaming a mapped Folder or Process at its source MUST be reflected on the next Process Map read without rewriting its placement.
25. Moving or resizing a placement within its current Explorer parent MUST change only Process Map geometry; crossing a Folder boundary MUST atomically use the canonical Company Explorer structural move and then synchronize the placement parent.
26. Mango MUST automatically create exactly one Process Map placement for every existing or newly created Company Explorer Folder and Explorer-placed Process, and MUST expose no independent manual add command.
27. Permanently deleting a Folder or Process MUST remove every Process Map placement, operational relationship, and trace that references its exact typed identity without affecting unrelated resources.
28. Recycling a Folder or Process MUST capture its Explorer structure, Process Map geometry, operational relationships, and traces promised for restoration before live cleanup occurs.
29. Restoring a recycled Folder or Process MUST restore its Explorer structure first, then restore exactly one matching Process Map placement and every separately promised operational relationship and trace.
30. Saved Process Map geometry MUST use global signed integer coordinates within -1,000,000,000 through 1,000,000,000 and positive integer dimensions no greater than 250,000,000; each rectangle's right and bottom edges MUST remain within the same coordinate bounds.
31. Every manually moved or resized placement and every manually routed point MUST snap to the smallest grid squares before it is saved.
32. Process Map placements and traces MUST be shared company state rather than personal browser state.
33. Every successful placement save MUST increment that placement's revision.
34. Placement saves MUST use last-committed-save-wins behavior and MUST NOT reject a save merely because the client read an older revision.
35. Every placement MUST record database-generated creation and update timestamps.
36. Every accessible Folder MUST be an elevated translucent surface that visually encompasses its contents; its visible name and perimeter select and move it, hover or selection reveals four corner resize grips, and its saved positive integer width and height are canonical placement geometry. The Folder surface MUST remain noninteractive so it does not place an opaque or invisible interior hit surface over contained placements or empty-canvas gestures.
37. Every accessible Process MUST be a movable, resizable neutral card whose saved positive integer width and height are canonical placement geometry.
38. Automatic placement MUST arrange Folders and Processes together from left to right in rows of at most six siblings inside each direct parent, with item seven starting the next row.
39. Every accessible Folder perimeter and Process card MUST keep one thin type outline matching Company Explorer: orange for a Folder and green for a Process; selection MUST preserve that type outline, Folder surfaces MUST remain interaction-transparent, and the map MUST show the current source name in readable dark text without a redundant `Folder` or `Process` caption.
40. A single click on an accessible Folder MUST select that Folder; a single click on an accessible Process MUST select that Process and pin its Process data card immediately to its right. Shift-dragging from empty canvas MUST draw one noninteractive selection rectangle and, in either drag direction, select every accessible Folder and Process whose full bounds including edges are enclosed; partial intersections and restricted placeholders MUST remain unselected, and the resulting selection MUST NOT invent bulk movement or deletion. Completing a placement drag or connection gesture MUST perform only that gesture and MUST NOT be treated as a click or open, close, pin, or unpin a data card.
41. A double click on an accessible Folder MAY fit the one existing camera to that Folder fence and MUST NOT navigate, change browser history, or open another semantic map.
42. A Process MUST remain a leaf on Process Map and MUST NOT open a Process Map child layer; double-clicking it, or pressing Enter or Space on the focused canvas while it is selected, MUST instead open that exact Process's canonical Logic Gate editor and Kanban page in the shared blocking overlay; a keyboard event from the Hover mode control, scorecard, or other interactive canvas descendant MUST retain its native control behavior and MUST NOT become a canvas command.
43. Panning or zooming MUST change only the current map viewport and MUST NOT enter or leave a Folder or change saved placement coordinates.
44. Process Map MUST have one stable company canvas URL, `/process-map`, and MUST NOT expose Folder-layer Process Map routes.
45. Zooming, panning, camera fitting, selecting, crossing a detail threshold, or opening the Process Logic Gate overlay MUST remain within the one company canvas and MUST NOT add browser history.
46. Copying and opening the Process Map URL MUST open the same company canvas for an authorized recipient without persisting another user's viewport or selection.
47. Browser Back MUST navigate only between real application pages and MUST NOT traverse camera positions, Folder focus states, or the Process Logic Gate overlay.
48. The initial Process Map scene read MUST return only permission-safe company bounds, tile/read version, and camera-loading metadata required to fit the whole authorized canvas.
49. Spatial tile reads MUST load only permission-safe geometry and presentation for genuinely missing tiles selected through deck.gl `TileLayer`'s bounded debounced scheduler, MUST return for each integer tile z only the conservative presentation superset an object can require anywhere in that z interval so fractional zoom needs no new request key, and MUST NOT use Explorer hierarchy or map-parent depth as the tile pyramid.
50. Process Map tile presentation MAY include only the current `America/Los_Angeles` business-day Q/C/D colors and resolved Responsible and Accountable labels needed for visible Process cards; it MUST NOT load QDC history, internal principal IDs, full Process documents, Nodes, emails, tasks, attachments, or a generic complete company relationship graph merely to draw the canvas.
51. Company Explorer structural hierarchy, Process Map geometry, operational relationships, and trace geometry MUST remain four separate meanings.
52. Company Explorer MUST be the sole structural parent authority, and its matching Process Map containment MUST NOT create or imply operational flow.
53. Runtime automatic placement, structural synchronization, map position, visual proximity, shared route geometry, Company Explorer ordering, and the placement backfill migration MUST NOT create, infer, change, or delete an operational relationship.
54. `resource_operational_relationships` MUST store the exact typed source and exact typed target of every operational relationship, and its create request MUST serialize each endpoint as exactly `{resource_type, resource_id}` without placement geometry, labels, permissions, or other presentation fields.

56. Every operational relationship MUST be directed, same-company, and non-self-referential.

65. Every Folder and Process MUST expose exactly one presentation-defined input anchor and exactly one presentation-defined output anchor derived from its current saved bounds, and those anchor locations MUST NOT be saved trace data.
66. A default saved trace or pending preview MUST leave the source horizontally before its first bend and enter the target horizontally after its final bend; those presentation-derived egress and approach segments MUST NOT become saved endpoint or route-point data.
67. Trace route geometry MUST be one ordered JSONB array of intermediate points expressed as snapped global company-world integer grid coordinates.
68. Trace JSONB MUST NOT copy endpoint resource IDs, resource types, names, permissions, operational direction, or other source payload.
69. Trace endpoint coordinates MUST be derived from current placements and their presentation-defined input and output anchors and MUST NOT be duplicated in the route-point array.
70. A trace route MUST be read and replaced as one small atomic value, and Process Map MUST NOT add bend, segment, junction, net, or route-node tables.
71. One-to-many flow MUST use several pairwise operational relationships whose traces MAY share the same route prefix.
72. Many-to-one flow MUST use several pairwise operational relationships whose traces MAY share the same route suffix.
73. An intentional visual junction MUST use the same explicit snapped grid point in every participating trace route.
74. A geometric crossing without a shared explicit route point MUST NOT be treated as a junction or operational relationship.
75. A visual junction or shared trunk MUST NOT become a Folder, Process, generic business resource, or operational relationship endpoint.
76. Rerouting the intermediate route points of a trace without changing its operational endpoints MUST preserve the operational relationship and increment the trace revision.
77. Trace saves MUST use last-committed-save-wins behavior and MUST NOT reject a save merely because the client read an older revision.
78. Every trace MUST record database-generated `created_timestamp` and `updated_timestamp` values.
79. Trace creation MUST set both trace timestamps, and a successful trace edit MUST preserve `created_timestamp` and advance `updated_timestamp`.
80. A failed trace write MUST change neither its route, revision, nor timestamps.

## Scenario: Fit nested Folders within the existing world

The default root size is `14 × 8^8` by `8 × 8^8`. At Folder level `L`, the preferred size is `14 × 8^(9-L)` by `8 × 8^(9-L)`. Each step reduces both dimensions eightfold, giving a 64-fold area reduction:

| Placement | Width | Height |
| --- | ---: | ---: |
| Folder level 1 | 234,881,024 | 134,217,728 |
| Folder level 2 | 29,360,128 | 16,777,216 |
| Folder level 3 | 3,670,016 | 2,097,152 |
| Folder level 4 | 458,752 | 262,144 |
| Folder level 5 | 57,344 | 32,768 |
| Folder level 6 | 7,168 | 4,096 |
| Folder level 7 | 896 | 512 |
| Folder level 8 | 112 | 64 |
| Process inside level 8 | 14 | 8 |

With regular children of the same aspect ratio at their preferred sizes, a Folder fits 30 siblings in six columns and five rows before extra shrinking is needed. Its title takes one eighth of its height, and its padding and gaps take one thirty-second of its height. Large sibling counts, unusually shaped manual placements, or crowding at the world boundary can consume this spare size and reduce the available nesting budget. Eight levels is the normal sizing budget, not a depth restriction or a guarantee for every crowded layout.

Six default roots with five gaps of 29,360,128 span 1,556,086,784 units, centered from −778,043,392 to +778,043,392 inside the two-billion-unit world. Coordinates remain signed integers between −1,000,000,000 and +1,000,000,000; each rectangle's far edges must also fit. The dimension cap is 250,000,000. Larger values do not increase placement count or the storage used by PostgreSQL's existing four-byte integer columns, but map extent and zoom affect tile coverage and serialized payload sizes. Drawing cost depends mainly on visible objects and tile work. The camera range remains −24 through +20 and tile zoom remains 0 through 22. At zoom +4, a 14 × 8 gate occupies 224 × 128 screen pixels. The renderer computes screen coordinates from the camera-relative position; pointer edits round back to integers, with exact halves toward positive infinity. Intermediate fitting calculations may use fractions, but saved rectangle edges and manual waypoints remain integers.

An operator must apply `20260902_process_map_nested_layout_capacity.sql` before deploying these defaults; it raises only the dimension constraint. Deployment, reads, and same-parent Explorer reordering preserve saved geometry. Reparenting scales and places the moved subtree; a required capacity fit can also transform its destination siblings. These transforms preserve relative arrangements and reject collapsed or invalid final geometry atomically.
