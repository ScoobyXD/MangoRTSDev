# Mango Pi runtime

Requires Node 22.19 or later. Run `npm ci --ignore-scripts` in `ai/runtime`, then `npm test`. Go starts `node ai/runtime/main.mjs` for each foreground Send and owns its 90-second deadline, authenticated tool calls, capture acknowledgments, cancellation, and shutdown. No service or MCP server is started. Each interaction validates its configured model against the installed Pi catalog before provider egress.

The official `@earendil-works/pi-coding-agent` and `pi-ai` packages are pinned to 0.85.0 in the lockfile. The published coding-agent entry point imports `pi-server` but omits that dependency, so the required official `@earendil-works/pi-server@0.85.0` is also pinned. Importing it does not run its server. No Pi package is patched or forked.

The published coding-agent also includes an npm shrinkwrap that pins nested copies of `pi-ai`, `pi-agent-core`, and `openai`. npm dedupe preserves those copies; our required direct imports and pi-server dependency use the outer copies. A clean install therefore still has two copies of those packages. Removing files by hand would not survive installation and is not part of this runtime.

The supported SDK `createAgentSession` uses an explicit ResourceLoader, native `loadSkills` with defaults disabled and the exact Process and Node chat skill paths, an in-memory model/credential/settings/session store, and a constrained native read operation. Only `AGENTS.md`, `skills/mango-process/SKILL.md`, and `skills/mango-node-chat/SKILL.md` can be read. The skill catalog and read tool expose the same portable paths relative to `ai`; only the runtime resolves their absolute filesystem locations. No automatic home/project context, packages, extensions, templates, telemetry, retries, compaction, shell, or general filesystem tools are enabled. Customer slash syntax remains literal text. The installed model must support the selected reasoning effort; unsupported selections stop before egress.

Go sends one JSON line with type `start`, its in-memory `api_key`, configured `model`, `reasoning_effort`, `messages`, `context`, mode-specific OpenAI-style function `tools`, and `limits`. Audit-only `audit_sources`, `tool_sources`, and `deploy_revision` describe those inputs without entering the model prompt. Production uses the official OpenAI Responses provider. An optional loopback-only `base_url` exists for local fake-provider tests; `test-model` is only recognized there and inherits the published gpt-5.6-luna metadata.

The child sends `capture` with an RPC `id` and `{kind,status,sequence,data}` event; it awaits Go's `ack` with the same ID before proceeding. A missing acknowledgment prevents further work. `tool` carries its RPC `id`, actual Pi `call_id`, `name`, and JSON `arguments`; Go replies `tool_result` with the same RPC ID and `result`, audit-only operation `audit_sources`, plus replacement `tools` and `tool_sources` after binding. Business tool dispatch stays inside Go. The child emits `text`, then `done` or a fixed safe `error`. Go ends failed interactions rather than sending error replies. Closing stdin aborts provider work and rejects pending RPCs; the Go supervisor kills the child on Stop, failure, or shutdown.

The final `agent.onPayload` wrapper awaits Pi's original transformations, applies fixed provider options, redacts secret URLs, captures the complete inspectable request, and awaits Go retention. Its exception occurs outside the extension dispatcher's swallowed-error path. The supported provider `fetch` option verifies that the SDK serialized exactly that body, disables redirects, and records dispatch after invoking fetch. Core `agent.subscribe` awaits required event capture; outer session listeners do not. Pi receives a sequential tool setting, and multiple calls in one model response are rejected before any dispatch. Native reads count toward the same 16-call budget. All function definitions, including native read and replacement catalogs, request Pi's supported `constrainedSampling: {type: 'json_schema', strict: 'require'}`; actual provider requests therefore retain `strict: true`.

Pi's streamed JSON parser repairs partial arguments, including malformed final strings, and discards the original strings from normalized events. A clone of each successful HTTP response is checked with the installed OpenAI SDK's public `Stream.fromSSEResponse` parser before any tool dispatch. The existing `openai@6.40.0` dependency is pinned directly for this parser; it makes no additional provider requests. The validator requires a completed response and completed tool items, uses strict `JSON.parse` on original final arguments (at most 32 KiB), and compares them with Pi's parsed arguments. Raw response bytes are bounded to 2 MiB before parsing. User input and the initial IPC request have no byte-length cap; execution, output, inspection, and provider capacity constraints still apply. Repeated provider call IDs cannot execute again even if the output item ID changes. Missing/incomplete/malformed/excessive output is recorded and stops work. Stop aborts both readers; there is still one Pi provider/tool loop.

The header Inspect button opens the latest Send's live events for every authorized user viewing their own conversation; each authorized Send streams traces automatically. Inspect distinguishes prepared/dispatched provider requests and actual tool results, including errors independently of continuation. It captures native skill bytes and hashes, effective system prompt including Pi's additions, exact sanitized request bodies, HTTP status on successful and rejected responses, usage, visible output, and security omissions. Each invocation includes a source snapshot covering actual loaded files and hashes, current tool definitions, context, history, and prior tool operations. Provider assembly paths resolve relative to the loaded coding-agent package, including its nested Pi provider dependency. Source metadata is audit-only; the captured provider body remains the actual sent JSON. Credential headers/private provider errors are never captured. Private reasoning and opaque continuation fields are explicitly omitted. Each Send archives its final inspection once in `ai_runs`; browser history and the current trace recovery endpoint remain in memory. Retention failure and size limits stop work before further unrecorded dispatch.

Adapter tests use the actual installed Pi session and OpenAI provider with a local HTTP fixture. They compare captured request bodies to received HTTP JSON for initial/continuation calls and exercise capture failure, native skills, isolation, binding, denied actions, cancellation, budgets, and no automatic retry. These are not paid provider or live-database tests.
