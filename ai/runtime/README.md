# Mango Pi runtime

Requires Node 22.19 or later. Run `npm ci --ignore-scripts` in `ai/runtime`, then `npm test`. Go starts `node ai/runtime/main.mjs` for each foreground Send and owns its 90-second deadline, authenticated tool calls, capture acknowledgments, cancellation, and shutdown. No service or MCP server is started. `node ai/runtime/main.mjs --check gpt-5.6-luna` verifies the installed SDK and local model catalog without credentials or network access.

The official `@earendil-works/pi-coding-agent` and `pi-ai` packages are pinned to 0.85.0 in the lockfile. The published coding-agent entry point imports `pi-server` but omits that dependency, so the required official `@earendil-works/pi-server@0.85.0` is also pinned. Importing it does not run its server. No Pi package is patched or forked.

The supported SDK `createAgentSession` uses an explicit ResourceLoader, native `loadSkills` with defaults disabled and one exact skill path, an in-memory model/credential/settings/session store, and a constrained native read operation. Only the four declared application assets can be read. No automatic home/project context, packages, extensions, templates, telemetry, retries, compaction, shell, or general filesystem tools are enabled. Customer slash syntax remains literal text. The installed model must support the selected reasoning effort; unsupported selections stop before egress.

Go sends one JSON line with type `start`, its in-memory `api_key`, configured `model`, `reasoning_effort`, `messages`, `context`, mode-specific OpenAI-style function `tools`, and `limits`. Production uses the official OpenAI Responses provider. An optional loopback-only `base_url` exists for local fake-provider tests; `test-model` is only recognized there and inherits the published gpt-5.6-luna metadata.

The child sends `capture` with an RPC `id` and `{kind,status,sequence,data}` event; it awaits Go's `ack` with the same ID before proceeding. A negative/missing acknowledgment prevents further work. `tool` carries its RPC `id`, actual Pi `call_id`, `name`, and JSON `arguments`; Go replies `tool_result` with the same RPC ID and `result`, optional safe `error`, or replacement `tools` after binding. Business tool dispatch stays inside Go. The child emits `text`, then `done` or a fixed safe `error`. Closing stdin or sending `cancel` aborts provider work and pending RPCs. The Go supervisor also kills the child on Stop or shutdown.

The final `agent.onPayload` wrapper awaits Pi's original transformations, applies fixed provider options, redacts secret URLs, captures the complete inspectable request, and awaits Go retention. Its exception occurs outside the extension dispatcher's swallowed-error path. The supported provider `fetch` option verifies that the SDK serialized exactly that body, disables redirects, and records dispatch after invoking fetch. Core `agent.subscribe` awaits required event capture; outer session listeners do not. Pi receives a sequential tool setting, and multiple calls in one model response are rejected before any dispatch. Native reads count toward the same 16-call budget. All function definitions, including native read and replacement catalogs, request Pi's supported `constrainedSampling: {type: 'json_schema', strict: 'require'}`; actual provider requests therefore retain `strict: true`.

Pi's streamed JSON parser repairs partial arguments, including malformed final strings, and discards the original strings from normalized events. A clone of each successful HTTP response is checked with the installed OpenAI SDK's public `Stream.fromSSEResponse` parser before any tool dispatch. The existing `openai@6.40.0` dependency is pinned directly for this parser; it makes no additional provider requests. The validator requires a completed response and completed tool items, uses strict `JSON.parse` on original final arguments (at most 32 KiB), and compares them with Pi's parsed arguments. Raw response bytes are bounded to 2 MiB before parsing, separately from the 512,000-byte request/context bound. Repeated provider call IDs cannot execute again even if the output item ID changes. Missing/incomplete/malformed/excessive output is recorded and stops work. Stop aborts both readers; there is still one Pi provider/tool loop.

Inspect distinguishes prepared/dispatched provider requests and actual tool results, including errors independently of continuation. It captures native skill bytes and hashes, effective system prompt including Pi's additions, exact sanitized request bodies, usage, visible output, and security omissions. Credential headers/private provider errors are never captured. Private reasoning and opaque continuation fields are explicitly omitted. Captures remain in Go/browser memory only; clearing or reloading loses browser history. Retention failure and size limits stop work before further unrecorded dispatch.

Adapter tests use the actual installed Pi session and OpenAI provider with a local HTTP fixture. They compare captured request bodies to received HTTP JSON for initial/continuation calls and exercise capture failure, native skills, isolation, binding, denied actions, cancellation, budgets, and no automatic retry. These are not paid provider or live-database tests.
